# SearchPaper — 论文检索、CCF 标注与归档

搜集用户指定范围的论文，交付有出处、可续跑的候选清单。默认中文输出，保留英文标题、正式出版信息和来源链接。

## 存储与续跑

- 默认根目录 `E:/paper`；用户指定其他位置时使用新位置，E 盘不可用时报告实际错误，不静默换盘。
- 按 [存储结构与续跑](references/storage-layout.md)，用 `paper_library.py new` 创建 `searches/{主题}/{日期时间}_{范围}/`。任务根目录提供 HTML 和启动器；`data/` 存结构化记录，`sources/` 存来源证据，`state/` 存收藏及导入回执，`_work/` 仅存临时中间产物。
- 更新/续跑先读取旧记录，按稳定 ID 合并，新建批次并用 `build --continue-from` 继承收藏与回执快照。保留原报告；复用已核对摘要与来源，只补缺项。
- 每次交付后用 `archive_index.py` 更新根目录的 `index.html` 总目录。历史报告纳入索引，默认保留原路径；不要把旧版 `_work` 当作可统一清理的缓存。

## 1. 确定范围

- 识别会议/期刊、年份或时间范围、主题、输出详略和是否要求 CCF 筛选。已给出的条件直接使用；没有指定会议时可跨来源检索，并声明范围。
- 对某一会议，默认搜集主会已录用/正式发表论文，覆盖官方实际存在的所有展示分组，如 Oral、Spotlight、Poster；不要默认只搜 Poster，也不要假设每个会议都有这些分组。
- 区分 `presentation_group`（展示方式）、`track`（主会/Findings/Workshop 等）和 `publication_type`（长文/短文/Demo 等）。主会短文可以收集但单独标明；Findings、Workshop 和预印本作为独立范围，按用户请求纳入，不能冒充主会长文。
- 默认添加 CCF 标签，不据此剔除论文或替代主题相关性排序。用户要求“只看 CCF A”等时，按经过核验且适用于该论文的等级筛选；待核实候选单列说明，不当作 C 类或未收录。

## 2. 获取列表和摘要

- 优先会议官网、正式论文集或出版页面；按实际出处选择 ACL Anthology、PMLR、OpenReview、出版社等。papers.cool 可辅助发现和抓取，openaccept.org 的数量可用于交叉检查，任一辅助站缺数据都不应阻断其他来源。
- 实际打开相应年份和分组页面，再使用其分页/API/下载接口。papers.cool 的 `show` 参数只是请求数量，不能证明返回完整；检查实际条目和下一页。OpenReview 上必须区分投稿、录用和最终发表状态。
- 为每条记录保存 DOI、OpenReview forum ID、ACL Anthology ID 或其他正式 ID；优先按稳定 ID 去重。缺少 ID 时可用规范化标题和作者/年份作为候选匹配，人工核验；同名或预印本与正式版本不能无条件合并。合并后保留各来源与展示分组。
- 按关键词、同义表达及摘要语义筛选，记录纳入/排除原因。标题不足以判断的候选继续读摘要；摘要获取失败标为待筛选，不计作不相关。
- 获取正式英文摘要，记录来源和访问日期。中文摘要忠实翻译；已有中文也注明来源并核对。原文、翻译与 AI 简短总结分字段保存；总结不能标成原始摘要，不能用标题编造缺失摘要。全文引用遵守来源可用范围。
- 批量翻译可使用当前可用的子 agent，按合理批次传递原文、paper_id 和输出目录；小批量直接完成。保留对应关系并复核，不为测试权限启动空任务。

## 3. 核对覆盖情况

- 对每个来源、年份、track 和展示分组记录 URL、预期数量及其来源（未知为 null）、获取条目数、去重数、已检查摘要数、命中数、待处理数和失败原因。
- 只有同一统计范围的数量可比较。分组可能重叠，不能简单求和；未去重总量不能当作论文数。
- 记录状态 `verified`（约定范围的分页/记录处理完成且核对无缺口）、`partial`（存在明确缺口）、`unverified`（完整性无法确认）。没有外部总数时可以记录分页已遍历，但不要声称“全部论文无遗漏”。覆盖核对仅针对声明的来源和范围，不保证主题筛选召回率。
- 失败时交付已核验的部分及待处理项。输出保留检索范围和缺口，续跑从保存的状态继续。

## 4. 添加 CCF 标签

每次搜集整理默认执行 [CCF 标注规则](references/ccf-classification.md)。先确认正式出版 venue 和论文类型，再核对官方目录版本；会议/期刊等级与单篇适用性分列。不同任务不要凭记忆沿用旧等级。

可用 `scripts/annotate_ccf.py` 将已经核实的出版元数据与指定目录快照合并，统一生成标签。它不联网、不识别论文内容，也不证明目录仍是最新版本；调用前按参考文档核实版本。内置快照只覆盖五个已核验会议，未匹配项继续查官方目录，不能据此断言未收录。

## 5. 交付与检查

默认按 [HTML 文献库与 Zotero](references/html-zotero.md) 使用固定模板生成 `index.html`、`data/library.json` 和 `打开论文库.cmd`，并记录 `manifest.json`。主展示为 HTML；`data/papers.json` 和 `data/coverage.json` 作为依据，Markdown 等文本导出放入 `exports/`。每次复用同一模板及渲染脚本，不临时重写页面布局。

按 [输出格式](references/output-format.md) 提供概览和可展开详情，至少包含标题、年份、准确 venue/track、CCF 标签及适用性、主题相关性、原文链接。每篇保留 Zotero 添加按钮、RIS 导出按钮和可用的原文/PDF 链接。目录版本及核验日期可在概览统一声明；每条仍须能定位到目录条目。

- 大批量默认先给概览表并附详细记录；用户指定详版时直接提供，不增加无必要的确认步骤。
- 核对表格与 JSON 的论文数、ID、来源、CCF 状态一致。保留缺失字段和未核实项，不补造数值。
- 在浏览器检查 HTML 的中文、长标题、筛选、摘要展开及移动端布局。Zotero 未打开时显示准确连接状态；仅收到成功响应才显示已添加，不在预览或测试时向用户真实文献库导入示例。
- `CCF A/B/C` 表示来源会议/期刊的推荐类别；论文是否值得阅读还依据内容、证据和用户研究方向。
